# Architecture, protocols and findings

## Layers
```
CLI (bin/ahkh.mjs)   MCP server (ahkh mcp)   hub daemon (TCP, token)      <- all call the same verbs
        +-------------- lib/verbs/*.mjs  (defineVerb: one definition = CLI verb = MCP tool = hub RPC)
                              |
                lib/session.mjs  Session = evidence Run + native host + processes + state (windows, dialogs, shots, findings)
                              |  JSON lines over stdio
                native host  bin/ahkh-host.exe  (C#, csc .NET 4, winexe: no console window)
                  - desk thread: SetThreadDesktop(hidden desktop); ALL window ops run here; 20ms watcher tick
                  - mon thread : stdout/stderr tail, exit, deadline
                  - guard thread + clipboard guardian (interactive session)
                  - per-target Job Object (kill-on-close, memory cap, UI limits): started suspended -> assigned -> resumed
                              |  lpDesktop = "WinSta0\AHKH_<pid>_<rand>"
                target processes (AutoHotkey, or anything)  <- optional AhkProbe.ahk via one /include
```
JS has **no npm dependencies**; it runs on node >= 18 and bun. The host dies with its controller (stdin EOF -> `Shutdown`; jobs are kill-on-close), verified by selftest and by killing the hub mid-session.

## Host protocol (`bin/ahkh-host.exe`)
Requests `{"id":1,"cmd":"win.list","proc":"main"}` -> `{"id":1,"ok":true,"result":...}` or `{"id":1,"ok":false,"error":"..."}`. Events (no id): `ready proc.start proc.exit proc.timeout out win.new win.ready win.gone win.hidden dialog shot hung unhung guard error`, each with `t` (ms since host start) and `ts`.
Commands: `proc.start|kill|info|list|metrics|deadline|dispose`, `rules.set`, `shots.auto`, `shot`, `win.list|tree|at|click|press|text|key|type|select|check|close|wmclose|minimize|maximize|restore|move|msg|mouse`, `uia.tree|act`, `guard.report|reset`, `clip.config`, `desk.info|list`, `sys.snapshot`, `img.info|crop|sheet|diff|annotate|pixel|dominant` (the image commands also work with `--images-only`, no desktop).
NB: `id` is the request id; process names travel as `proc`.
`shot` takes `tech: auto|composed|printwindow-full|printwindow|windowdc|screen|bitblt|composite`, `composed`, `isolate`, `bg`, `flush`, `rect`, `scale`, `maxEdge`, `path`; composed results add `layers[] {hwnd,class,pid,rect,method,ms,note}`, `unreadable[] {…,why}`, `composeMs`.
Threads: **desk** (watcher, input, everything window-related), **comp** (`Host.Compose.cs`: attached to the same desktop, owns the cloaked compositor windows + a message-only window, pumps messages, runs every `shot`), **mon**, guard. comp never waits on desk (`OnDesk` runs inline on comp), so desk -> comp waits cannot deadlock.
Targets get `AHKH_HOST_HWND` (message-only window: `WM_COPYDATA`, dwData `'AHKH'` = 0x484B4841, UTF-16 JSON `{"cmd":"shot"|"ping",…,"reply":"file.json"}`; returns 1 ok / 2 error, result JSON in `reply`) and `AHKH_CURSOR_MAP` (shared memory: int x, y, seq, buttons of the synthetic cursor).

## Dialog rules
`{name, match:{kind,class,title,text,button,proc}, do:{shot,press,type,close,kill,ignore,delayMs,verdict}}`, first match wins, user rules before `rules/default.json`. `press`: `"default" | "safe" | "first" | "kill" | "close" | "<button text>" | {id:N} | {button:"..."}`.
Kinds are structural: AHK v2's error dialog owns a RichEdit (id 501) and buttons 65400/65401/65405/65411 (Reload/Edit/ExitApp/Help); warnings are the same dialog with Abort (id 2) hidden. Locale independent. `safe` = Cancel, No, Abort, Ignore, Continue, OK - never Yes/Retry (used by smoke).

## Probe protocol
Stdout lines `AHKH|<kind>|<json>` (`error assert step done log mark bench`). RPC (rpc mode only, so a permanent timer never changes when a script would exit): mailbox files `probe/in/NNNNN.json` -> `probe/out/NNNNN.json`, polled every 40ms inside the target. Commands `ping guis menus menufire hotkeys fire call get set log exit shot unexclude reexclude` (`call` resolves `Class.Method`). In-script API: `Ahkh.Shot(path, opts)` (composed shot via `AHKH_HOST_HWND`). At load, if `GetCursorPos` fails (non-input desktop) on 64-bit AHK, the probe redirects user32!GetCursorPos (a 12-byte `mov edx,1; jmp [rip+x]` stub, layout checked first) to read `AHKH_CURSOR_MAP`. Wrappers installed via `DefineProp` on `Gui.Prototype.*`, `Gui.Control.Prototype.OnEvent`, `Gui.Prototype.OnEvent`, `Menu.Prototype.Add` record what the script builds; `fire` runs handlers *inside* try/catch so errors come back structured.

## Findings from spikes (verified in the sandbox, AutoHotkey 2.0.19)
| question | answer |
|---|---|
| Inject a probe without editing the script? | Yes: `/include file` keeps `A_ScriptFullPath`. **Only one `/include` is honoured** (two -> exit 2, silent); the harness merges into `prelude.ahk`. |
| Can a script override built-ins (`SetTimer`)? | Yes, but the original becomes unreachable -> timers/OnMessage are found statically and called by name via `call`. |
| Can `Gui.Prototype.AddButton`, `Gui.Control.Prototype.OnEvent` be wrapped? | Yes (`Add` alone does not see `AddButton`; each `Add*` is wrapped). |
| Fire hotkeys without keyboard input? | Yes: post `WM_HOTKEY` (0x312, wParam = index in definition order) to AHK's hidden main window; works for plain, `$` hook and `~` hotkeys. `ListHotkeys` gives the order. |
| UIA on the hidden desktop? | Inspection and `setvalue` work (managed UIA on a thread attached to the desktop). `Invoke`/`Toggle` on plain Win32 buttons throw -> use `press`/`check`. |
| Screenshots on the hidden desktop? | `PrintWindow(PW_RENDERFULLCONTENT)` works, even for hung windows; the ladder falls back to `PrintWindow(0)`, window DC, screen BitBlt; desktop shots are composited window by window. |
| Hang detection? | A plain AHK `Loop` still pumps messages; block in a `DllCall("Sleep")` to test. Detected via `SendMessageTimeout(ABORTIFHUNG)`, reported after 4s. |
| Does the job's clipboard limit protect the clipboard? | **No**: it blocks `SetClipboardData` but `EmptyClipboard` succeeds and wipes the user's clipboard (caught by selftest). Fixed by the clipboard guardian (snapshot + restore on `WM_CLIPBOARDUPDATE` when the owner is one of our pids). |
| Private window station for full isolation? | `CreateWindowStation` with a name -> access denied; with a NULL name it works (`Service-0x0-...$`). But windows in a non-interactive station are never visible (`WSF_VISIBLE` cannot be set): AHK GUIs exit and `MsgBox` never shows. Kept as `--station` (opt-in), useless for GUI targets. |
| Desktop enumeration | `EnumDesktops` needs a Unicode delegate (`CharSet.Unicode`) or names arrive truncated to one character. |
| **What would the screen show?** (Win11 Home 26300, 2026-10-11) | Screen BitBlt of the hidden desktop reads black (DWM never presents it). **WGC** `CreateForWindow` on a hidden-desktop window: item size 0x0, `StartCapture` -> `ERROR_INVALID_STATE` (also with a forced pool size); from another desktop the HWND does not even validate (err 1400). Monitor capture / Desktop Duplication only see the *input* desktop (= the user's screen: never used). dwmapi #100 (`DwmpDxGetWindowSharedSurface`) returns S_OK with a NULL handle. **But DWM does keep the hidden desktop's visual trees**: `DwmRegisterThumbnail(own window, hidden window)` succeeds with the right source size, and `PrintWindow(own window, PW_RENDERFULLCONTENT)` makes DWM render the own window *including the thumbnail* - even when that window is cloaked (`DWMWA_CLOAK`) and off screen (not when it is hidden). Rendered over a black and a white host, the pair gives exact per-pixel alpha (difference matting). That is the composed shot: per-window, bottom to top, "over". 6-30 ms per window, ~100-800 ms per desktop. |
| ... what each window type gives | UpdateLayeredWindow per-pixel alpha: exact (matte 227/26,143,228 vs 227/24,143,228 expected). DirectComposition incl. #147 shared thumbnail visuals and 3D transforms (Deep/Cube): yes. DWM thumbnails inside a `WS_EX_NOREDIRECTIONBITMAP` window: yes. Trident (Shell.Explorer) pages: yes (GDI PrintWindow: blank). DWM caption/border/text colours, rounded corners, DWM 1px border: yes. `SetLayeredWindowAttributes` alpha/colour key: **ignored by thumbnails** -> re-applied from `GetLayeredWindowAttributes`. Mica/acrylic/tabbed: their solid fallback colour (no blur). Window shadows: no. |
| ... windows excluded from capture | `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`: the thumbnail renders black. `DwmGetDxSharedSurface` (user32) still returns the redirection surface of normal/LWA windows (opened with D3D11 `OpenSharedResource`, raw vtables, read via a staging texture) -> used for those. UpdateLayeredWindow windows have no shared surface (err 1): an excluded *layered* window is unreadable from outside -> the probe lifts its own process' exclusions for the moment of the shot (`unexclude`/`reexclude`, `Ahkh.Shot`). |
| **PrintWindow on an UpdateLayeredWindow window** | **Destroys its content**: the window shows whatever WM_PRINT painted (an AHK GUI: flat F0F0F0) until its owner calls UpdateLayeredWindow again. The old desktop composite did exactly that to every overlay it shot. Now never done (GDI ladder skips PrintWindow for them; DWM renders them). |
| Direct2D / DXGI windows on a non-input desktop | Notepad++'s DirectWrite Scintilla (SCI_GETTECHNOLOGY = 1) never shows its text on the hidden desktop (neither in GDI nor DWM captures); `SCI_SETTECHNOLOGY 0` (GDI) and it does. Apps that honour DXGI/D2D "occluded" skip drawing there - not a capture limit, the pixels do not exist. |
| Input on the hidden desktop | `GetCursorPos` **fails** there (FALSE; AHK MouseGetPos returns garbage), `WindowFromPoint` works and implements real routing: alpha-0 pixels of UpdateLayeredWindow windows and click-through layered windows pass to the window below (measured with the composed canary). Low-level hooks only receive real input of the input desktop; `SendInput` would go to the user. -> `win.mouse` (routing + WM_NCHITTEST/SETCURSOR/MOUSEMOVE/MOUSELEAVE/buttons/wheel, posted) + the probe's GetCursorPos redirect to a shared-memory synthetic cursor. |
| **Console programs started by a target** (Win11 default terminal) | A NEW console (`Run("powershell ...")` from AHK, `start`, ShellExecute, CREATE_NEW_CONSOLE) is handed by the inbox conhost to the default terminal via out-of-proc COM (OpenConsole `IoDispatchers.cpp` `_shouldAttemptHandoff`); Windows Terminal runs outside the job and opened an EMPTY window on the USER'S desktop. No handoff when: console inherited, CREATE_NO_WINDOW, STARTF_USESHOWWINDOW with hide/minimise, conhost started with a command line, ConPTY/headless, session 0, invisible window station. A GUI process started with a pseudoconsole does NOT pass it to its console children (spike: each got a fresh conhost). That conhost is started by its client, so it is **in our job**: the host gets `JOB_OBJECT_MSG_NEW_PROCESS` on an I/O completion port and terminates it before it reaches the connect message (the client dies with 0xC0000142 = it never connected, and the handoff is decided while handling that connect): finding `console-blocked` (warn). Allowed: a console target's own windowless console (CREATE_NO_WINDOW, inherited by its children) and `console: true` (`conhost.exe -- cmdline`, window on the hidden desktop; no std handles, or conhost becomes a VT pty over them -- and leaving STARTF_USESTDHANDLES out is not "no std handles": the console child then gets the host's OWN std handles, its RPC pipes, and conhost read the host's requests as keyboard input for cmd and wrote VT into the event stream (every request after it "timed out", the hub went down). So: STARTF_USESTDHANDLES with three NULL handles, bInheritHandles FALSE; selftest "a console window ... never reads or writes the host's own pipes"). Guard backstop: a job process whose console server is not System32\conhost.exe = delegated -> LEAK `console-delegated`, client terminated, new Windows Terminal windows closed. Selftest: `console-children.ahk` + before/after window list of the real desktop. |
| **A crash while the process exits** | An access violation under ExitProcess / DLL detach (measured: an AHK script exiting with an OLE drop target registered on a Trident window -- AHK frees the script's objects, then mshtml revokes the target and OLE calls Release through freed memory) leaves **exit code 0**: the run said PASS while Windows Error Reporting wrote a dump. The host checks for that process's local dump (`%LOCALAPPDATA%\CrashDumps\<exe>.<pid>.dmp`, written before the process handle is signalled; newer than its start) on every exit not caused by the harness: `crashed: true`, name `crashed (Windows Error Reporting dump ...)`, field `werDump` -> CRASH. Note WER keeps only the newest 10 dumps (LocalDumps DumpCount): crashing repros push older dumps out. |
| Windows 11 26xxx IME windows | Every GUI process gets `UAC_InputIndicatorOverlayWnd` / `UAC Input Indicator` top-level windows (another thread, always responsive) above its GUI: the hang check now probes the process' biggest window, not the first in z-order. |

## Design decisions
- **Message-based input, never `SendInput`.** SendInput targets the input desktop (yours); messages target an HWND on the hidden one. Buttons are pressed with a *posted* `BM_CLICK` so a click that opens a modal dialog cannot block the harness.
- **Evidence first.** Every event is appended to `events.jsonl` (monotonic ms + wall clock). Per-item files, never a monolithic JSON cache (the AST harness' 204 MB cache lesson). Retention via `keepRuns`.
- **Ground truth ordering:** AutoHotkey `/Validate` > language server > AST parser (experimental). `lint` shows disagreements.
- **Originals are never modified.** Shadow copy under the run folder (bounded: 6000 files / 250 MB), patches applied with a code-aware mask (strings, comments and continuation sections are not code), out-of-tree `#Include`s made absolute, patched files + diff + line map archived as `effective/`.
- **Smoke safety:** shadow copy, `stub-dangerous` recipe, label deny-list, `press: safe` for dialogs, keep-going so one error doesn't hide the next, budgeted and seeded (same seed = same order).
- **The reducer locks onto the original finding's signature** (paths/numbers normalised); otherwise ddmin happily reduces to a *different* bug.

## Not done / known limits
- Registry and network are not virtualised (only files via the shadow copy, plus the destructive-call stubs).
- There is no way to synthesise real key events on the hidden desktop (use `hotkey.fire`); the same for low-level-hook mouse input, `GetAsyncKeyState`, raw input and real drags. Hover/click routing and the cursor position are simulated (`mouse`).
- Composed shots: no backdrop blur (Mica/acrylic as solid colour), no window shadows; an excluded-from-capture layered window of a process without the probe is unreadable (hatched); content an app never draws on a non-input desktop (D2D/DXGI "occluded") cannot appear. The compositor's two windows (class `AhkhCompositorB/W`, cloaked, at -32000,-32000) are visible to a script that enumerates every window.
- UIA-only controls (WebView2 content, custom-drawn) are inspectable but not always drivable without real input.
- The AST parser is experimental; its errors are informational.
- `responsive` in `windows` is a 150 ms probe; the authoritative hang signal is the `hung` event (4 s).
